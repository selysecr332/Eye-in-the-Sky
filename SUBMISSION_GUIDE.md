# Guide for instructors & TAs

This package is designed so each milestone is **self-contained** and **easy to grade**.

## What to open first

1. **[README.md](README.md)** — table of all HW folders.
2. **`HW_n/README.md`** — learning goals, artifacts, checklists.
3. **`HW_n/diagrams/*.md`** — Mermaid diagrams (render on GitHub or paste into [mermaid.live](https://mermaid.live) for PNG).

## Grading affordances

| Element | Why it helps |
|---------|----------------|
| Per-HW **checklists** | Quick verification of completeness |
| **Relative links** to code under `AirSim/` | Honest traceability, no copy-paste drift |
| **Diagrams as `.md`** | Version-controlled; diffs visible in PRs |
| **TODO (student)** markers | Student fills name, links, dates — obvious gaps |

## Optional quick verification (technical)

If the course requires a **demo**, the canonical runbook is repo root **`RUN_DRONE_FIND_THINGS.md`** and **`README.md`**.

## Academic integrity

Students should list **what is original** vs. **upstream** (AirSim / PX4 licenses). PDFs in `HW_*` must be their own work or properly cited.
